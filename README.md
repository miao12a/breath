# 先呼吸一下 · 搭建手册

一个零成本的「one sec 替代方案」。核心是一个网页版呼吸训练页 `breath.html`，
配合 iOS 快捷指令自动化 + 系统屏幕使用时间，实现：**打开某个 App → 直接开始呼吸 → 问你要不要继续 → 30 分钟后再拦一次**。

不需要 Mac、不需要 Xcode、不需要 $99 开发者账号、不需要上架 App Store。

## 零、实际流程长什么样

```
你点抖音
  ↓ 快捷指令自动跳转（无确认框）
呼吸页直接打开，立刻开始 3 轮 4-4-6 呼吸（约 45 秒）
  ↓
问「现在还想用它吗？」
├─ 不想了，关掉它 → 结束页，回桌面。闭环成立
└─ 还是想用一会儿 → 30 分钟倒计时
                      ↓ 到点自动回到呼吸页 → 第二次干预
```

没有校准页、没有欢迎页、没有任何"开始"按钮——**打开就是呼吸**，一步都不多。

---

## 一、为什么是这个方案

原生 iOS App 走 `FamilyControls` + `ManagedSettings`（也就是 one sec 的实现方式）需要
`Family Controls (Development)` entitlement，而**这个权限不对免费 Apple ID 开放**。
结果就是：代码能编译、模拟器正常，但装进真机时签名失败。

所以这里换一条路：

| | 原生 App | 本方案 |
|---|---|---|
| 需要 Mac | 是 | 否 |
| 需要 Xcode | 是 | 否 |
| 需要付费开发者账号 | **是** | 否 |
| 能上系统级盾牌 | 是 | 否（借系统屏幕使用时间） |
| 改一版要多久 | 编译+重签 | 刷新浏览器 |

**代价必须说清楚**：本方案没有强制力。你能忽略限额、能按掉闹钟、能直接划走这个页面。
它给你的是一个**犹豫的窗口**，不是一道锁。真正拦得住你的是下面第 4 步的系统限额。

## 二、文件说明

```
breath.html      ← 全部内容都在这一个文件里（约 40KB，零依赖，可离线）
README.md        ← 你正在看的这份
_acl-report/     ← 系统自动生成的权限修复记录，含回退命令，别删
```

`breath.html` 不联网、不加载任何外部资源、不收集任何数据。所有设置存在浏览器 localStorage 里。

**默认参数**：3 轮 4-4-6 呼吸（吸 4 秒 / 屏 4 秒 / 呼 6 秒），继续使用时长 **30 分钟**。
想改就在页面里的「设置」调，或者用快捷指令的 URL 参数覆盖（见第七节）。

> 文件里有一段 `window.__breathTest` 测试钩子，用途是让自动化测试不必真等 30 分钟。
> 它只读写你自己浏览器里的本地设置，不联网、不上传任何东西，留着无害。

## 三、部署（三选一）

### 方式 A：电脑上先看效果（最快，30 秒）

双击 `breath.html`，用浏览器打开即可。建议按 `F12` 打开开发者工具，点手机图标切到 iPhone 视图，
这样看到的排版和真机接近。想测试"点开就呼吸"，直接在地址栏加参数：

```
file:///H:/a项目/breath.html?minutes=5&rounds=3
```

### 方式 B：手机同一 WiFi 下访问（真机体验，5 分钟）

在电脑上起一个本地服务（`H:\a项目` 目录下执行）：

```powershell
# 如果你装了 Python
python -m http.server 8000

# 或者用 Node
npx serve -l 8000
```

然后查电脑的局域网 IP：

```powershell
ipconfig | Select-String "IPv4"
```

假设得到 `192.168.1.5`，手机 Safari 打开：

```
http://192.168.1.5:8000/breath.html?minutes=5&rounds=3
```

⚠️ 这个地址只在**同一 WiFi 下、电脑开机时**有效。电脑一关就没了，
所以适合调试，不适合长期用。

### 方式 C：部署到免费静态托管（长期使用，推荐）

手机在任何网络下都能打开，电脑不用开机。任选一个：

**GitHub Pages**
1. 注册 GitHub 账号，新建一个 **public** 仓库，比如 `breath`
2. 把 `breath.html` 改名成 `index.html` 上传上去
3. 仓库 `Settings → Pages → Source` 选 `main` 分支，保存
4. 等 1~2 分钟，访问 `https://你的用户名.github.io/breath/`

**Cloudflare Pages / Vercel / Netlify** 同理，拖拽上传即可，国内访问 Cloudflare Pages 通常比 GitHub Pages 稳。

**国内访问提示**：如果 GitHub Pages 打开很慢或打不开，用 Cloudflare Pages，
或者干脆用方式 B 并把电脑设成不关机。

**部署完请记下你的完整网址**，第 5 步要用。

### 可选：加到主屏幕，看起来像个 App

Safari 打开你的网址 → 底部「分享」→「添加到主屏幕」。
之后从主屏幕图标进入是全屏的，没有地址栏。注意：**从主屏幕进入的页面和 Safari 里的是两套独立存储，
设置要重新配一次**。

## 四、配置系统屏幕使用时间（真正的强制力）

这一步才是真正拦得住你的东西，别跳过。

1. 打开 **设置 → 屏幕使用时间** → 开启
2. **App 限额** → 添加限额 → 选「社交」或具体某个 App（抖音、小红书）
3. 时长设成你真正希望的上限，比如 30 分钟
4. 打开 **「阻止使用」**（到限额后直接屏蔽）

到了限额，iOS 会弹出**系统级全屏拦截页**，上面有一个 **「15 分钟后提醒我」**——
这就是一个天然的、你赖不掉的"二次干预"计时器。

> **想更狠一点**：设置 → 屏幕使用时间 → 打开 **「使用屏幕使用时间密码」**，
> 让家人帮你设一个你不知道的密码。这样「忽略限额」这条路就被堵死了。
> 这是整个方案里唯一真正的强制手段。

## 五、配置快捷指令自动化（核心步骤）

打开 **快捷指令** App → 底部 **「自动化」** → 右上角 **「+」** → **「App」**。

### 5.1 创建触发

1. **App** 选你要戒的那个（比如抖音）
2. 勾选 **「已打开」**
3. 选择 **「立即运行」**（不要选"运行前询问"）
4. 关掉 **「运行前询问」** 开关

### 5.2 添加动作

搜索并添加 **「打开 URL」**（在 Safari 分类下），填入你的地址。

**不知道填什么就用这个**（等于全用默认值：3 轮呼吸 + 30 分钟）：

```
https://你的网址/breath.html
```

想微调就带参数，比如呼吸狠一点、3 轮改成 4 轮：

```
https://你的网址/breath.html?rounds=4&minutes=30
```

如果你用方式 B（局域网），把域名换成 `http://192.168.x.x:8000`。

> 页面里的「设置」和 URL 参数是**同一个配置**：URL 参数只在带参数打开时覆盖，
> 平常自己点开用的是上次保存的设置。所以最省心的做法是——**用页面里的设置调好一次，
> 之后快捷指令里就填不带参数的干净地址**。

保存即可。

### 5.3 ⚠️ 必须验证这一步真的生效

**建好之后，真的去点一次抖音。** 确认它自动跳到呼吸页、且**没有弹确认框**。

如果弹了确认框：
- 回到自动化里重新检查「运行前询问」是否被关掉
- iOS 更新有时会把这个开关**偷偷打开**，建议每次系统更新后都检查一遍
- 实在关不掉，就删掉自动化重新建一个（迁移过来的旧自动化有时不认这个设置）

### 5.4 🔴 防死循环：打乒乓球问题的解药（必做）

**症状**：你在呼吸页跳到小红书 → 小红书一打开，自动化又把你扔回网页 → 无限循环。

**原因**：这不是 bug，是 Shortcuts 的机制。自动化监听的是系统级的「App 已打开」事件，
**只要你用 deeplink 跳回 App，这个事件就一定会再触发一次**。网页没有任何办法
"恢复原始的打开流程"——Apple 没给这个 API。

> 原生 App 在 iOS 26 上能靠 App Intents 的 `.foreground(.dynamic)` 在后台静默挡掉，
> 但网页做不到。所以网页方案必须自己做一个"冷却"。

#### ⚠️ 一个必须知道的 Shortcuts 陷阱

**「打开 URL」会把 Safari 切到前台，同时这次快捷指令就结束了——它后面的动作不会执行。**

这意味着**任何"打开 URL 之后再写文件"的设计都是无效的**。所以下面的方案
**所有判断和写文件都在「打开 URL」之前完成，后面一个动作都没有**。

如果你真想验证这一点：把「打开 URL」放在最前面、后面放个「快速查看」，
你会发现快速查看永远不弹。

#### 解法：用文件的"修改时间"当冷却标志

思路很简单——**看这个文件多久之前被改过**：

- 文件刚刚（20 秒内）被改过 → 说明用户是在从呼吸页跳回来的路上 → **放行，不再拦**
- 文件很久没动过 → 说明是一个全新的打开 → **正常打开呼吸页**

每次"放行"时顺手把文件再碰一下，冷却窗口就自动续上了。这样不需要任何收尾动作。

#### 操作步骤

**① 先建一个文件**

1. 打开「文件」App → 进 **iCloud 云盘** → 新建文件夹 `Breath`
2. 在里面新建一个文本文件，命名 `lastopen.txt`，内容随便填个 `0`
3. 确认它就叫 `lastopen.txt`（扩展名不要变成 `.txt.txt`）

**② 自动化里只放这 8 个动作，顺序不能变**

| 顺序 | 动作 | 参数设置 |
|---|---|---|
| 1 | **获取文件** | 选 `iCloud 云盘/Breath/lastopen.txt`；**关掉「显示文稿选择器」** |
| 2 | **获取文件的详细信息**<br>（Get Details of Files） | 详细信息选「**修改日期**」，文件选第 1 步的结果 |
| 3 | **获取日期之间的时间**<br>（Get Time Between Dates） | 第一个日期：第 2 步的结果<br>第二个日期：「**当前日期**」<br>单位：「**秒**」 |
| 4 | **如果** | 条件：第 3 步的结果 **小于** `20` |
| 5 | └ **存储文件** | 存到 `iCloud 云盘/Breath/`，文件名 `lastopen.txt`，**打开「覆盖」**（内容随便，可填 `x`） |
| 6 | └ **停止此快捷指令** | 放在「如果」里面 |
| 7 | **结束如果** | |
| 8 | **打开 URL** | `https://miao12a.github.io/breath/?app=xhs` |

**它怎么跑的**：

| 情况 | 文件修改时间 | 走哪条路 |
|---|---|---|
| 用户正常点开小红书 | 很久以前 | 第 4 步判断为假 → 跳过 5、6 → 执行 8，打开呼吸页 |
| 从呼吸页跳回小红书（乒乓） | 刚刚（20 秒内） | 第 4 步判断为真 → 碰一下文件、**停止**，不拦你 |

放行那次把文件碰了一下，于是"20 秒冷却"重新开始计时。

#### 关键点

- **第 2 步别选成「创建日期」**，要用「**修改日期**」
- **第 3 步单位一定选「秒」**，不然数字对不上
- 第 1 步一定要关掉「显示文稿选择器」，否则每次弹选择框
- 第 5 步一定要打开「覆盖」，不然会存出一堆副本，读到的就不是同一个文件了
- 这套逻辑 **每个 App 的自动化都要各配一份**（文件可以共用同一个）

#### 已知的副作用（能接受）

- **20 秒内快速重开小红书不会被拦。** 想更严就把 `20` 改小（比如 `8`），
  但要保证比呼吸页跳回去的时间长，否则乒乓又会回来
- **如果你选「不想了」然后一直停在呼吸页**，文件停在 20 秒冷却内；
  等你 20 秒后再开小红书，照样会被拦，没问题

> **调试技巧**：在「文件」App 里长按 `lastopen.txt` → 显示简介，看「修改日期」。
> 每次点开小红书，如果时间是刚刚，说明冷却是放行分支走通了。

> **懒人替代方案（完全不用碰文件）**：页面设置里把「选继续用之后」改成
> **「停在倒计时页，我自己点打开 App」**，然后**用 App 切换器手动切回小红书**——
> 手动切换通常*不会*触发自动化，也就没有乒乓问题了，代价是每次要多点一下。

### 5.5 适用版本（本机为 iOS 18）

**第五节这套流程是针对 iOS 17 / 18 写的**，本机 iOS 18 完全适用。

| 环节 | 最低版本 | iOS 17 / 18 上的写法 | 旧版差异 |
|---|---|---|---|
| 「App」触发器 | iOS 13 | 选 App → 勾「已打开」 | 一致 |
| **立即运行** | **iOS 17** | 选「**立即运行**」，关掉「运行前询问」 | iOS 16 及更早叫「运行前询问」开关，位置在自动化编辑页顶部，且**部分触发类型不给关**，会每次弹确认框 |
| 获取文件 | iOS 13 | 搜索「**获取文件**」 | 一致 |
| 文件属性 | iOS 13 | 搜索「**获取文件的详细信息**」，选「修改日期」 | 一致 |
| 算时间差 | iOS 13 | 搜索「**获取日期之间的时间**」，单位选「秒」 | 一致 |
| 条件判断 | iOS 13 | 搜索「**如果**」 | 一致 |
| 提前结束 | iOS 13 | 搜索「**停止此快捷指令**」 | iOS 12 上叫「停止快捷指令」 |
| 写文件 | iOS 13 | 搜索「**存储文件**」，打开「覆盖」 | iOS 15 之前可能没有「覆盖」选项，需要先「删除文件」再存 |

**经过验证的动作参数**（来自 [Shortcuts 动作参考](https://350ml.net/shortcuts/gettimebetweendates.html)）：

- 「**获取日期之间的时间**」的「单位」可选：总时间 / **秒** / 分 / 小时 / 日 / 周 / 月 / 年
  → 5.4 用的就是「秒」
- 「**获取文件的详细信息**」的「详细信息」可选：文件大小 / 文件扩展名 / 创建日期 /
  **修改日期** / 名称 → 5.4 用的就是「修改日期」

**和 iOS 26 的关系**：如果以后升到 iOS 26，原生 App 可以用 App Intents 的
`.foreground(.dynamic)` 在后台静默挡掉这次跳转，就**不需要 5.4 这套冷却标志**了。
但网页方案在 iOS 26 上也还是得用冷却标志——那个 API 只对原生 App 开放。

**几个叫法上的不确定点**（iOS 小版本之间措辞会变，你按意思找就行）：

- 「获取文件」里那个开关可能叫「**显示文稿选择器**」或「**选择多个**」，
  你要的是**关掉它**，让动作直接读指定路径
- 「存储文件」的覆盖选项可能显示为「**覆盖（如果文件存在）**」

## 六、再把"二次干预"补到接近原生

快捷指令只能做到"打开 App 时先呼吸"。要做出"N 分钟后再干预一次"，
用下面两个办法叠上去，**建议两个都开**：

### 6.1 页面自带倒计时（已实现）

在呼吸结束的询问页选「还是想用一会儿」，页面就会开始倒计时（默认 **30 分钟**），
到点自动弹回询问页再让你呼吸一次。

- 倒计时**跨页面存活**：切去刷抖音、甚至 Safari 把页面回收了，回来还会接着算
- 到点时如果页面在后台，会发一条浏览器通知（需要允许通知权限）

### 6.2 快捷指令加一个计时器（强烈建议）

在同一个自动化里，**在「打开 URL」之后**再加一个动作：

**「开始计时器」** → 设为 30 分钟（和页面里的倒计时保持一致）

这样到点时手机真的会响，而且**刷得正起劲的人必然会去关它**。对戒断来说，
这个恼人的闹钟比任何温柔的提醒都有效。倒计时结束的那一刻，正好是你重新做决定的一刻。

### 6.3 用通知做提醒（需要加到主屏幕）

只有把网页**添加到主屏幕**后，iOS 才允许网页发通知。
允许之后，倒计时到点会推一条通知："该再呼吸一次了"。

## 七、URL 参数参考

所有参数都是可选的，写进快捷指令的 URL 里就能覆盖本地设置。

| 参数 | 含义 | 范围 | 示例 |
|---|---|---|---|
| `minutes` | 继续使用多久后再次干预（默认 30） | 1–180 | `minutes=30` |
| `rounds` | 呼吸轮数，越多拦截感越强（默认 3） | 1–20 | `rounds=3` |
| `inhale` | 吸气秒数（默认 4） | 2–30 | `inhale=4` |
| `hold` | 屏息秒数，设 0 则跳过（默认 4） | 0–30 | `hold=7` |
| `exhale` | 呼气秒数（默认 6） | 2–30 | `exhale=8` |
| `auto` | 呼吸完自动选「继续用」，不问你 | 0/1 | `auto=0` |
| `returnAfter` | 选「继续用」之后的行为，见下表 | — | `returnAfter=stay` |
| `scheme` | 目标 App 的 URL Scheme | 文本 | `scheme=xhsdiscover://` |
| `app` | 用简称代替 scheme | 见下 | `app=xhs` |

**`returnAfter` 的四个取值：**

| 值 | 行为 | 什么时候用 |
|---|---|---|
| `stay` | **默认**。选完「继续用」1.4 秒后自动跳回 App | 最顺手，但**必须配 5.4 的冷却** |
| `ask` | 停在倒计时页，自己点「打开 App」 | 想手动控制什么时候回去 |
| `none` | 停在倒计时页，连按钮都不给 | 最狠，强制你面对倒计时 |
| `minutes` | 留作扩展，目前等同 `stay` | — |

**`app=` 支持的简称**：`douyin`（抖音）、`xhs`（小红书）、`bilibili`、`weibo`、`zhihu`

**完整示例**——打开抖音时强制 3 轮 4-7-8 呼吸，然后给 5 分钟，到点自己跳回抖音：

```
https://你的网址/breath.html?minutes=5&rounds=3&inhale=4&hold=7&exhale=8&auto=1&app=douyin
```

> `auto=1` 请谨慎使用。它会自动帮你跳回 App，但会跳过"问你要不要继续"这一步。
> 戒断效果最好的是 `auto=0`，让你每次都亲手做一次选择。

## 八、常见问题

**Q：呼吸页打开是白屏 / 没反应？**
按顺序试：① 确认能上网（方式 A 需文件路径正确）② 强制关闭 Safari 重开
③ 清掉 Safari 缓存 ④ 换 Chrome 试，排除浏览器问题。

**Q：点抖音没有自动跳转？**
九成是「运行前询问」没关掉，或者 iOS 更新重置了它。见 5.3。

**Q：跳过去了，但抖音已经开在前面了？**
正常。快捷指令的触发是在 App 启动之后，所以会先闪一下抖音再跳到呼吸页。
介意的话，去 **设置 → 屏幕使用时间 → App 限额** 把抖音也限上，双保险。

**Q：我在跳回小红书，结果又被扔回呼吸页，来回打乒乓球！**
这是 Shortcuts 的机制限制，不是 bug。解决办法见 **5.4 防死循环**。
最快的临时缓解：设置里把「选继续用之后」改成 **「停在倒计时页，我自己点打开 App」**，
然后用 App 切换器手动切回小红书。

**Q：呼吸页里我没设 scheme，选"继续用"之后回不去？**
回桌面自己点就行。想一键跳回去，在设置页里填入目标 App 的 URL Scheme
（小红书是 `xhsdiscover://`，抖音是 `snssdk1128://`）。**这个值只能自己试**——App Store 更新有时会改。

**Q：点「回桌面」没反应？**
网页没有关闭自己的能力，需要一个能跳出浏览器的 scheme。
在设置里把「回桌面用的 scheme」填成 `shortcuts://`，点回桌面就会跳到快捷指令 App，等于离开浏览器。

**Q：一打开就开始呼吸了，我想先调设置怎么办？**
故意的，这个版本去掉了校准页和欢迎页，打开即呼吸。
**呼吸页右上角就有「设置」**，点进去调，保存后回到结束页，再回桌面即可。

**Q：倒计时到点没提醒我？**
① 页面必须在后台存活才会跳动，被彻底杀掉就不会响 ② 必须允许了通知权限
③ 所以务必开 6.2 的快捷指令计时器兜底。

**Q：能拦微信 / 系统 App 吗？**
不能直接拦系统 App。快捷指令的 App 触发器对大部分第三方 App 有效，微信有时不稳。

**Q：数据会上传吗？**
不会。所有内容只存在你自己浏览器的 localStorage 里，页面本身也不联网。

### ⚠️ 网络：`github.com` 需要代理

这台机器上 **`github.com` 和 `raw.githubusercontent.com` 连不上**（TLS 握手超时），
但 `api.github.com`、`codeload.github.com`、`objects.githubusercontent.com` 是通的。实测结果：

| 域名 | 直连 | 说明 |
|---|---|---|
| `api.github.com` | ✅ 通 | 所以 `_upload.js` 走 API 一直好使 |
| `codeload.github.com` | ✅ 通 | 所以 `git clone` 能成功 |
| `github.com` | ❌ 超时 | 所以 `git push` 必须挂代理 |
| `raw.githubusercontent.com` | ❌ 不通 | 图片、raw 文件取不到 |

**代理端口是 `127.0.0.1:7897`，已写入 git 全局配置：**

```ini
[http]
	proxy = http://127.0.0.1:7897
[https]
	proxy = http://127.0.0.1:7897
```

代理没开的时候 git 会卡住直到超时。临时绕过：

```powershell
git -c http.proxy= -c https.proxy= clone https://github.com/miao12a/breath.git
```

彻底取消代理配置：

```powershell
git config --global --unset http.proxy
git config --global --unset https.proxy
```
